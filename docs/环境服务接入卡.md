## 数据源与字段映射

| 数据 | 当前适配器 | 字段 / 单位 | 覆盖、时区与使用边界 |
| --- | --- | --- | --- |
| 天气 | [Open-Meteo Weather Forecast API](https://open-meteo.com/en/docs) | `temperature_2m`：°C；`wind_speed_10m`：km/h（请求固定 `wind_speed_unit=kmh`）；`uv_index`（UV index）：指数；保留 API `current.time` 作为 `observedAt`，逐时数据标记为预测。 | API 文档列出最多 16 天预测；请求 `Asia/Shanghai`（未来应替换为机构时区）。来源署名显示为 **Weather data from Open-Meteo.com** 并链接官方文档。 |
| 潮汐 | [QWeather Tide API](https://dev.qweather.com/en/docs/api/ocean/tide/) | `tideTable` 的 `H` / `L` 归一为高潮 / 低潮；`tideHourly` 高度以 m 保存；始终保留站点 ID 和响应时间。 | 使用站点 LocationID 和 `YYYYMMDD` 日期；文档范围为今天起最多 10 天。**垂直基准未知**：API 契约没有说明潮高垂直基准，所以 `verticalDatum=null`、`verticalDatumStatus=unknown`，不跨站点或跨基准比较。 |
| 海浪 / 海面高度 | [Open-Meteo Marine API](https://open-meteo.com/en/docs/marine-weather-api) | `wave_height`：m；`sea_level_height_msl`：m，字段改名为 `modelSeaLevelHeightMsl`。 | 海洋预报文档最多 8 天。波高与站点潮高按逐小时字符串时间分别保存。模型海面高度参考全球平均海平面，不是当地潮汐站潮高，**不用于潮高规则**；产品文档说明海岸附近准确度会降低，且不适合航海导航。 |

官方来源链接用于页面署名和数据口径查阅；本地合成 fixture 不是这些服务的实时返回，不显示为真实来源数据。Open-Meteo Weather 和 Marine 对应 API 页面分别说明字段、单位、时区与预测范围；QWeather 潮汐接口的潮高基准未在接口契约中声明。

## API Host、认证和凭证获取

- QWeather 当前适配器使用 `X-QW-Api-Key` 请求头。其官方认证文档也支持 JWT；如机构选择 JWT，应作为单独的部署配置与验收变更，不要把 JWT 拼进查询 URL。
- 必须使用该 QWeather 账号对应的**账号专属 API Host**。从 QWeather 控制台的项目 / API 凭证设置中查看 host 与 key，并从账户下潮汐站查询页面确认 LocationID。不要把旧共享 `api.qweather.com` 或 `devapi.qweather.com` 当账号 host；QWeather 已公告 2026 年开始逐步淘汰旧共享域名。
- Open-Meteo 的公开 Forecast API 适配不设置 API 凭证。若未来套餐或机构代理要求凭证，由部署者按所购服务配置，不写进代码、测试输出、截图或报告。
- 将 key 放在部署密钥管理中，以服务器进程环境变量传入。Stage14 不读取 `.env`，不要求用户在本地添加 key，也不输出 key 值。自动测试只使用本地 HTTP stub 和无敏感含义的测试字符串。

## 显式启用模式的配置边界

服务默认不联网；只有获准的调用显式设置 `ENVIRONMENT_MODE=live` 并设置 `ENVIRONMENT_LIVE=1` 后才会进入提供方适配分支。源端Q27.6已按用户选定模式对Open-Meteo做过一次有界实测，不代表生产配置或持续服务。当前代码的Open-Meteo模式需要位置ID/名称、经纬度和时区；大连开发区地区代表点可用于明确标记的地区级展示验收，但不等于机构精确地址。启用QWeather台站适配器时，再额外要求站点和账号配置。

1. `ENVIRONMENT_LOCATION_ID`
2. `ENVIRONMENT_LOCATION_NAME`
3. `ENVIRONMENT_LATITUDE`（-90 至 90）
4. `ENVIRONMENT_LONGITUDE`（-180 至 180）
5. `ENVIRONMENT_TIME_ZONE`（有效 IANA 时区）

仅选择QWeather台站潮汐适配器时还需：`QWEATHER_TIDE_STATION_ID`（与地点匹配的QWeather LocationID）、`QWEATHER_API_HOST`（账号专属host）和`QWEATHER_API_KEY`。选择Open-Meteo默认模式时无需这些QWeather字段。位置/时间配置缺失或经纬度无效时，相应数据域返回unavailable并显示缺失项，不发请求；API key值不会进入缺失列表、响应、日志或用户界面。Open-Meteo endpoint可由`OPEN_METEO_WEATHER_BASE_URL` / `OPEN_METEO_MARINE_BASE_URL`覆盖以接入获准网关；默认值指向官方公开API。

即使未来配置齐全并成功读取实时数据，也不能按本卡中的 demo 阈值给出可参加结论。当前还没有机构批准的 UV/潮高/波高安全阈值配置；实时数据可以展示，但项目时段仍须待确认。live provider 只提供原始 `uvIndex`，显示分类留为 `unknown`；可用性只会用已批准的机构阈值从原始 UV 重新判定，不读取 provider 上的展示标签或 demo 阈值。只有后续完成机构阈值来源、版本和人工审批设计后，才允许独立启用安全窗口判定；未确认前不会返回 live `available`。

环境依赖按项目类型区分：室内项目不依赖天气、潮汐或海浪；陆上户外项目需要有效天气和 UV；下海项目还需要有效潮汐站潮高与海浪。缺失或过期只会阻止依赖该数据域的项目时段；所需域未齐全时保持 pending。

## 缓存和安全降级

- 快照以地点、站点、日期和数据域建立唯一键；相同 provider 响应重复写入幂等。
- 默认有效期：天气 30 分钟、海况 30 分钟、潮汐 2 小时。有效缓存复用；过期后刷新成功才成为 fresh。刷新失败时可返回 `stale` 供展示；天气/UV 缺失或过期会让户外项目待确认，潮汐或海浪缺失或过期会让下海项目待确认。室内项目不因无关环境域阻断。
- 没有缓存且服务失败时返回 `unavailable` / 空字段。前端显示暂无数据和限制原因；不会用 0、晴天默认值或模型文字填补。
- 页面与 API 保留 `snapshotId`、目标日期、来源、数据时间、有效期、演示标志和限制说明。潮汐曲线只用站点 `tideHourly`；海浪与模型海面高度分列。
- 阶段14 的正常 / 高潮 / 大浪 / 强 UV 阈值用例仅验证接口和状态流。它们不等于真实可预约或安全结论；本阶段不创建预约、不扣容量。
