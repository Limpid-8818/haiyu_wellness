# 海屿康养社区开发者启动手册

这份手册面向第一次拿到仓库的开发者。当前交付是本地开发版：默认 SQLite、离线环境数据和安全助手引导模式。它不提供单一的生产部署脚本，也不把当前验收状态解释为 109 条需求全部通过。

## 1. 获取与前置条件

```bash
git clone https://github.com/Peppa12138/haiyu_wellness.git
cd haiyu_wellness/项目源码
node --version
npm --version
npm ci --ignore-scripts
```

要求 Node.js `>=22.13.0`、npm `>=10`。项目使用 npm workspaces，唯一有效的锁文件是 `项目源码/package-lock.json`；不要用 pnpm 替代 npm。所有 npm 命令都从 `项目源码/` 执行。

Node 22.13.0 之后可以直接使用内置 `node:sqlite`。如果启动时报 `node:sqlite` 不存在，先检查 `node --version`，不要给 Node 加旧版本的实验参数。

## 2. 本地配置与 SQLite

复制示例配置，并为本地账号生成随机签名密钥：

```bash
cp .env.example .env
node --input-type=commonjs <<'NODE'
const fs = require('node:fs');
const secret = require('node:crypto').randomBytes(32).toString('hex');
const source = fs.readFileSync('.env', 'utf8');
if (!/^AUTH_SECRET=.*$/m.test(source)) throw new Error('.env 中缺少 AUTH_SECRET 配置行');
fs.writeFileSync('.env', source.replace(/^AUTH_SECRET=.*$/m, `AUTH_SECRET=${secret}`));
NODE
```

这会替换 `.env` 中的占位值，避免留下重复的 `AUTH_SECRET` 配置项。

`.env` 已被 Git 忽略，不能提交。不要把真实密钥、真实用户库或运行日志写入仓库。

默认配置使用 SQLite：

```dotenv
DB_DRIVER=sqlite
DB_PATH=./data/community-v2.sqlite
```

`DB_PATH` 的相对路径按 `server` workspace 的工作目录解析，因此上面的值对应 `项目源码/server/data/community-v2.sqlite`。父目录会在 API 初始化时创建。第一次启动会执行迁移；新库不会自动创建演示账号。

需要演示账号时，只对一个新的空库显式设置 `DEMO_SEED=1`：

```bash
DEMO_SEED=1 npm start
```

演示账号如下，仅用于本地：

| 角色 | 账号 | 密码 |
| --- | --- | --- |
| 客人 | `guest_demo` | `guest2026` |
| 工作人员 | `staff_demo` | `staff2026` |
| 院长 | `dean_demo` | `dean2026` |

在首页选择对应角色入口后填写账号和密码。新库没有演示账号时，客人可从客人入口选择注册；工作人员和院长账号由机构侧管理。

## 3. 一条命令启动前后端

```bash
npm run dev
```

默认地址：

- 网页：`http://127.0.0.1:5180`
- API：`http://127.0.0.1:3020/api`
- 健康检查：`http://127.0.0.1:3020/api/health`

Vite 将 `/api` 代理到 `API_PROXY_TARGET`。API 启动脚本会读取 `项目源码/.env`；命令行显式变量优先。

API 的标准入口也会启动 Stage25 内置每日服务定时器，启动时执行一次检查，此后每分钟检查一次；当前没有关闭配置。它可能写入本地数据库，所以启动前应确认 `DB_PATH` 指向自己的开发库。

## 4. 分开启动

终端一启动 API：

以下两个终端均从仓库根目录开始；如果已在 `项目源码/`，省略 `cd 项目源码`。

```bash
cd 项目源码
PORT=3020 DB_PATH="$PWD/server/data/community-v2.sqlite" npm start
```

终端二启动 Vite：

```bash
cd 项目源码
WEB_PORT=5180 API_PROXY_TARGET=http://127.0.0.1:3020 npm run dev -w web
```

端口冲突时，同时修改 API、网页端口和代理目标：

```bash
PORT=24520 WEB_PORT=25520 API_PROXY_TARGET=http://127.0.0.1:24520 npm run dev
```

只改 `WEB_PORT` 而不改 `API_PROXY_TARGET` 会导致网页能打开但 API 请求失败。停止服务使用各终端的 `Ctrl-C`；API 会停止定时任务、关闭 HTTP 服务和数据库连接后退出。重新启动前确认旧端口已经释放。

## 5. 构建与本地生产形态

构建网页：

```bash
npm run build
```

产物位于 `web/dist/`。当前 API 没有把 `web/dist/` 挂载为 Express 静态目录，因此仓库没有“一条命令同源托管前后端”的生产服务器。可以分别运行：

```bash
# API
PORT=3020 npm start

# 本地检查构建产物，Vite preview 默认使用 WEB_PORT + 1
WEB_PORT=5180 API_PROXY_TARGET=http://127.0.0.1:3020 npm run preview -w web
```

正式部署需要一个静态文件服务器或反向代理托管 `web/dist/`，并把 `/api` 转发到 Node API；这属于部署方配置，不是当前仓库已经提供的生产部署实现。不要把 Vite preview 当成生产服务。

## 6. 助手与模型配置

没有同时设置 `LLM_BASE_URL` 和 `LLM_API_KEY` 时，助手使用安全引导/规则协作模式，不会发起模型请求。需要本地验证兼容模型服务时，在 `.env` 中填写：

```dotenv
LLM_BASE_URL=https://兼容 OpenAI Chat Completions 的服务地址
LLM_API_KEY=本机私密值
LLM_MODEL=服务支持的模型名
```

修改配置后必须重启 API。密钥不会发送给浏览器，也不要把它写入 issue、日志或提交。`LLM_TIMEOUT_MS` 默认 20 秒，最大按 120 秒计算；缺失、非正数或无效值使用默认值。

当前仓库已有安全降级和本地规则路径。真实模型连通、usage、持续外部环境服务和生产质量评测仍需单独授权与验收；不要把界面显示的模式状态当成真实 provider 证据。

## 7. 可选 MySQL

MySQL 只用于明确隔离的本地/测试实例，不要指向用户库或生产库。必须显式设置 `DB_DRIVER=mysql`，并提供 MySQL 8.x 实例的连接信息：

```dotenv
DB_DRIVER=mysql
MYSQL_HOST=127.0.0.1
MYSQL_PORT=3306
MYSQL_USER=haiyu_local
MYSQL_PASSWORD=本机私密值
MYSQL_DATABASE=haiyu_wellness
```

连接错误不会回退到 SQLite。服务启动时会检查 MySQL 主版本必须为 `8.x`，随后执行现有迁移。迁移、字段映射、导入和回退边界见[SQLite/MySQL 迁移与回退](MySQL迁移与回退.md)。

## 8. 常见问题

**端口被占用。** 用 `lsof -nP -iTCP:3020 -sTCP:LISTEN` 或对应端口确认占用者。为 API 设置新的 `PORT`，为 Vite 设置新的 `WEB_PORT`，并让 `API_PROXY_TARGET` 指向新的 API 地址。不要停止不属于本次开发的用户服务。

**网页打开但请求失败。** 检查 API 是否返回 `GET /api/health`，再检查 Vite 的 `API_PROXY_TARGET` 是否包含正确端口。修改 `.env` 后需要重启 Vite。

**登录签名无效或启动提示默认密钥。** 确认 `.env` 中的 `AUTH_SECRET` 已替换为随机值，并且 API 重启后读取到了它。不要使用源码中的默认值。

**SQLite 文件锁或脏数据。** 停止所有使用该文件的 API 进程；开发测试优先使用新的临时路径，不要删除仍被进程打开的目录或日志。SQLite 的 `-wal`/`-shm` 文件和数据库文件都属于运行数据，不提交 Git。

**模型请求没有发生。** 这是无 key 时的预期行为。确认 `LLM_BASE_URL` 与 `LLM_API_KEY` 同时非空，并重启 API；不要把安全引导结果称为真实模型调用。

**MySQL 报缺少连接变量或版本不支持。** 检查 `DB_DRIVER=mysql`、`MYSQL_PORT`、`MYSQL_USER`、`MYSQL_DATABASE` 和密码是否齐全，并确认服务器是 MySQL 8.x。服务不会静默改用 SQLite。

**`npm ci` 失败。** 从仓库根目录进入 `项目源码/`，使用 Node 22.13+ 和 npm 10+，不要混用根目录遗留的 pnpm 文件。若锁文件与 package.json 不一致，应先检查分支和未提交改动，不要删除锁文件强行安装。
