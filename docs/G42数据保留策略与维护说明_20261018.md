## 删除单位与时间

总开关默认关闭，手动命令默认 preview，显式 enabled + apply + maintenance 确认才写。服务注入 db / transaction / clock，不导入 db.js。CLI 只连接显式已有数据库，不迁移、不种子、不创建默认文件，不接 HTTP 或 scheduler。preview 使用只读连接和只读快照；apply 在新事务里重新扫描、判断、按依赖删除。维护时应暂停应用写入，只支持单维护进程；事务不是在线跨进程图锁保证。

| 表 | 判断时间/状态 | 单位与保留理由 |
| --- | --- | --- |
| assistant_sessions | started_at、last_message_at、expires_at；closed/expired，或 active 但确实已过期 | 有效时间都须严格早于截止，未知状态/非法时间保留；整组保留 |
| agent_runs | created_at、updated_at、completed_at；completed/failed/interrupted | queued/running 保留；parent_run_id、session_id 连接完整图 |
| agent_steps | started_at、completed_at；completed/failed/reused | running、缺终态时间保留；run_id 连接运行 |
| tool_executions | started_at、completed_at；completed/failed/reused | run_id/step_id 连接图，不能留下半条来源链 |
| assistant_messages | created_at | session_id/run_id（后者无 FK）连接跨会话图；近期消息保留全组 |
| mood_resource_events | played_at | 仅旧无引用事件行；不删资源文件/目录/账本 |
| audit_logs | created_at | 独立默认关闭；启用后仅旧 login 且 target_type=user 可清，其余业务、健康、审批、动作、鉴权变更及未知类别长期保留 |

窗口示例运行90天、事件90天、审计180天；截止相等和不规范 UTC 日期保留。批量以实际行数计，完整组超预算就跳过，不拆图。

为覆盖上述字段与嵌套来源，实现扫描当前29版所有55张应用表的完整行（含迁移中创建的 job_capability_settings，不输出内容），包括全部 JSON、文本及元数据 FK；这是有界的完整判定。先读取有界列长度，再加载预算内文本，序列化后再次核字节。固定表白名单；缺表/新表/迁移不符、非InnoDB、视图或触发器拒绝维护。字符串 ID 出现在嵌套 JSON 或自由文本也视为引用；数字目标使用 FK、明确字段名或 type/id 配对，避免将不同表的数字主键混淆。目标内部的图引用形成连通组，持久业务行和保留审计的引用保护全组。非法声明 JSON、二进制、超深/超字节/扫描不完整拒绝 apply，并报告原因；不会猜没有引用。

## 验证与使用

服务为 `server/src/data-retention.js` 的 `runDataRetention({config,mode,maintenance,clock,openDatabase})`；连接由注入函数返回 `{db,transaction,close}`。连接必须是独占维护连接，transaction须保证整段callback原子性。`finally` 关闭连接。`db.js`、原公开门面和正常启动不变；CLI 的专用适配器共享既有 G23 编译/参数/结果工具。SQLite URI `mode=ro/rw` 限定已有文件，preview连接原生只读；MySQL使用只读事务或普通写事务。

在 `项目源码` 下，先通过部署环境显式设置 `DB_DRIVER`。SQLite还需绝对路径的已有 `DB_PATH`；MySQL必须显式给出 `MYSQL_HOST/PORT/USER/DATABASE/PASSWORD`（空密码也需明确存在）。CLI不加载.env，账号凭据不放在CLI参数中。默认禁用无需任何数据库配置：

```sh
npm run maintenance:retention
# {"status":"DISABLED","mode":"preview","databaseOpened":false}
npm run maintenance:retention -- --enabled --run-days 90 --mood-days 90
# PREVIEW：不改行；--preview / --dry-run 同义，省略时也是preview
npm run maintenance:retention -- --enabled --apply --maintenance
# APPLIED：先暂停应用写入，仅一个维护进程；重新判断而非使用上次preview清单
npm run maintenance:retention -- --enabled --audit-enabled --audit-days 180
# 单独预览审计授权；仍只有旧login/user类别可删
```

总开关、审计授权用显式CLI flag，避免服务环境的普通启动自动启用删除。窗口1..36500整天、batchSize1..1000、scanRows1..20000、scanBytes1..16777216、groupRows1..1000。`--batch-size/--scan-rows/--scan-bytes/--group-rows` 对应同名配置。重复/未知/冲突参数拒绝；apply缺enabled或maintenance拒绝。退出0为DISABLED/PREVIEW/APPLIED，错误退出1。输出截止UTC、扫描行/字节、组数，各表scanned/candidates/selected/protected/deleted与原因计数；候选但因batch上限跳过的行也计protected。无有效删除的apply仍正常输出0。
