## 二、总原则

1. **先机械、后行为**：阶段 1–3 只搬运代码（剪切-粘贴-补 import），不改任何逻辑；阶段 4 的行为性改动在文件已拆小之后做，每项独立提交、独立可回退。
2. **DOM 契约冻结**：拆分期间不改任何 className、id、aria 属性、可见文本、组件层级。本项目验收与演示脚本直接依赖 DOM 选择器（如 `login-*`、`role=tab`）。唯一例外是阶段 4 的 G12（登录引言渲染方式）与 G02（预填值），已在计划中单列。
3. **每步可验证**：每个提交必须 `npm run build`（web）通过；每个阶段结束跑一次 `npm test`（server，当前 122/122，预期不受影响）；阶段 2 每搬完一个域做一次浏览器抽查。
4. **先粗后细**：每个域一个文件（约 200–600 行），不追求一个组件一个文件。标签常量跟着所属域走。

## 三、分支与提交策略

- 分支：`fix/20261015-frontend-reorg`（已创建，基于合并后的 main）。
- 提交粒度：阶段 1 约 4–5 个提交；阶段 2 每个域一个提交（约 12 个）；阶段 3 约 2–3 个；阶段 4 每个条目一个提交；阶段 5 约 2 个。提交信息前缀 `refactor(web):` / `feat(web):` / `chore(web):` / `test(web):`。

### 阶段 4 · 行为性改进（约 1.5–2 天，每条目独立提交）

按依赖顺序：

1. **G20 统一数据加载**：新增 `lib/useQuery.js`（generation 守卫 + 可选 AbortController，语义与现有手写守卫一致），替换 grep 到的全部 12 处 `useEffect(() => { load(); }, [load])` 样板，并把现有 4 处手写 generation 守卫收敛到同一 hook。迁移处逐一人核对 loading/error 时序不变。

3. **G19 二级错误边界**：GuestView/StaffView/DeanTeam/AssistantWidget 四个分发点各包一层复用的 ErrorBoundary。
4. **G18 + G36 代码分割与依赖纠正**：StaffView、DeanTeam、AssistantWidget 改 `React.lazy` + Suspense（guest 为主线保首屏）；`vite`/`@vitejs/plugin-react` 移入 devDependencies；记录分割前后 bundle 体积对比。
