# 演示模式使用指引

> 面向本地演示与交接场景：如何让各岗位登录后都有内容可看。合成数据均带"（演示）"标记，不代表真实业务、库存或安全批准。

## 1. 三条演示数据路径

| 路径 | 什么时候用 | 效果 |
| --- | --- | --- |
| `DEMO_SEED=1` 启动（[开发者启动手册](开发者启动手册.md)） | 只需要基础登录演示 | 新空库写入 guest_demo / staff_demo / dean_demo 三个账号（guest2026 / staff2026 / dean2026） |
| `npm run demo:team`（[五岗位演示配置](../archive/docs/五岗位演示配置与阶段2复验_20261013.md)） | 需要**专用隔离演示库**（不碰现有库） | 按 1014 交接文档 §4.2 在指定路径创建带标记的专用库并写入五岗位账号 |
| `npm run demo:mock`（本文档） | 在**当前开发实例**上快速铺一套完整演示数据 | 五岗位 + 两名演示客人 + 全链业务数据（下文） |

`demo:mock` 与前两者不冲突：它向当前 API 实例增量补数据，幂等可重复执行。

## 2. demo:mock 快速开始

```bash
# 前置：开发实例已启动（默认 3020/5180）
cd 项目源码
npm run demo:mock
```

- 脚本会先检查 `/api/health`，实例未启动会直接退出并提示。
- 所有写操作尽量走真实 API（校验、幂等键、审计齐全）；仅疗程草案与历史心情因 API 依赖模型/仅限当天而用 SQL 直写。
- **幂等**：已存在的账号/对象自动跳过，重复执行安全；如需全新重跑，删除 `server/data/community-v2.sqlite*` 后以 `DEMO_SEED=1` 重启再执行本脚本。
- 可用环境变量覆盖目标：`DEMO_API`（默认 `http://127.0.0.1:3020/api`）、`DEMO_DB`（默认 `server/data/community-v2.sqlite`）。

## 5. 演示讲解建议路线

1. 院长登录 → 员工账号（五岗位）→ 客人分工。
2. 医护登录 → 疗程审核（顾斌 v2 待审、4 项、强制复核）→ 我负责的客人（岑心待核实自述）。
3. 配餐员登录 → 备餐工作台（午餐备餐中）。
4. 客人B 登录 → 管家（每日简报）→ 日程（预约与草案）→ 膳食（已送达早餐）→ 心情与陪伴（7 日趋势）→ 健康记录（血压趋势）。
5. 智能助手按 `.env` 配置工作：配置了 DeepSeek 即真实模型（live），未配置则为安全引导模式。

## 6. 边界与红线

- 菜品、供货、排期、容量均为演示目录数据；页面顶部的"本地网页演示"边界声明由产品保证，不要移除。
- 预约只使用非海上项目（水疗）；海上项目在环境资料缺失或机构阈值未配置时会被安全门拒绝，这是设计行为，不要为演示绕过。
- 疗程草案为 SQL 构造的合成证据（来源标记 `demo_seed`），用于展示界面与审核流程，不等同于真实模型生成的方案。
