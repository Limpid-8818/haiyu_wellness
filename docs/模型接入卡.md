# 海屿康养社区模型接入卡

更新日期：2026-09-27
范围：记录现有 OpenAI-compatible Chat Completions 适配器的配置与协议；本页是接入说明，不代表已连接或验证真实模型。

## 官方协议

本项目当前的适配器使用 OpenAI Chat Completions HTTP 接口。官方参考说明该操作为 `POST /chat/completions`，请求包含 `model` 和按顺序排列的 `messages`；非流式成功响应为 Chat Completion 对象，文本从 `choices[0].message.content` 读取。OpenAI 官方文档也提示新项目可优先评估 Responses API；本卡沿用仓库已有的兼容接口形状，便于替换支持相同协议的服务。

- [OpenAI 官方：Create chat completion](https://developers.openai.com/api/reference/cli/resources/chat/subresources/completions/methods/create)
- [OpenAI 官方：API authentication](https://developers.openai.com/api/reference/overview#authentication)
- [DeepSeek 官方：模型与 API 地址](https://api-docs.deepseek.com/quick_start/pricing/)
- [DeepSeek 官方：Chat Completions API](https://api-docs.deepseek.com/api/create-chat-completion/)

## 环境变量对应位置

| 变量 | 当前本地 DeepSeek 配置 | 适配器用途 |
| --- | --- | --- |
| `LLM_BASE_URL` | `https://api.deepseek.com` | HTTP API 基地址。适配器会追加 `/chat/completions`；也可直接配置完整路径。 |
| `LLM_API_KEY` | 在 `项目源码/.env` 中填写，初始为空 | 发送到服务端请求头 `Authorization: Bearer <LLM_API_KEY>`。不得放进浏览器代码、提交到 Git 或回传给客户端。 |
| `LLM_MODEL` | `deepseek-flash` | 放进 JSON 请求的 `model` 字段；必须是账号和所选服务支持的模型 ID。 |
| `LLM_TIMEOUT_MS` | 本地 `.env` 为 `60000`；源码默认 `20000` | 请求超时毫秒数；适配器最多接受 `120000`。 |

`npm start` 和 `npm run dev` 的 API 进程会读取 `项目源码/.env`，已有 shell 环境变量优先。更换支持 OpenAI Chat Completions 的服务时，只需调整地址、模型 ID 和 key。当前 DeepSeek 模型默认启用思考模式；本适配器发送的 `temperature` 在该模式下不会生效。

只要同时设置非空 `LLM_BASE_URL` 与 `LLM_API_KEY`，`GET /api/assistant/status` 就会报告 `live=true`；该状态仅表示已配置，不验证 DNS、鉴权、余额、模型权限或服务连通性。

## 请求示例

以下命令使用变量占位符，不含真实凭证，也不应携带真实健康资料：

```sh
curl --max-time 60 https://api.deepseek.com/chat/completions \
  -H "Authorization: Bearer ${LLM_API_KEY}" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "deepseek-flash",
    "temperature": 0.25,
    "messages": [
      {"role": "system", "content": "You are a helpful community assistant."},
      {"role": "user", "content": "请介绍入住咨询流程。"}
    ]
  }'
```

适配器不启用流式响应。请求成功应是 HTTP 2xx、可解析的 JSON，并含非空字符串 `choices[0].message.content`；应用将该字符串作为助手回复显示。示例成功文本：`入住咨询可以先了解房型、办理流程和服务安排。`

## 失败与降级判定

出现非 2xx HTTP 状态、网络错误、超时、无效 JSON，或缺少非空 `choices[0].message.content` 时，适配器视为模型调用失败，不将其标记为模型成功；聊天响应改用本地安全引导回复并返回 `live=false`、`mode=安全引导模式`。当前适配器不自动重试。`LLM_TIMEOUT_MS` 源码默认 20 秒，本地 `.env` 为 60 秒，配置值最多按 120 秒处理。

## 隐私与验收边界

- API 密钥只留在服务器环境；本仓库不放真实密钥，本卡也不含真实密钥。
- Q7.11/Q7.12 使用本地 HTTP stub 验证请求与降级，不访问真实模型服务、不产生付费调用。
- 禁止把真实客人资料或健康数据粘贴进手工 API 请求。现有后端发给兼容模型的授权客人上下文会排除姓名、电话、房间号、出生日期和紧急联系人；模型输出仍是辅助文字，不会自动写入正式病历或发布医嘱。
