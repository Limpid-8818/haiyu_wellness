## 变更一：基础设施工具统一（G44）

**问题**：`FOR UPDATE` 锁后缀在 9 个业务模块各有一份拷贝（命名各异 `LOCK`/`lockSuffix`/`guestLock`/`lock`）；"有事务则加入、无则开启"的 `inTransaction` 帮手 4 处逐字重复 + 4 处内联；重复约束（unique violation）判定 6 处 3 种语义变体；`stableJson` 两份（assistant.js 与 assistant-actions.js，含 Date 分支的等价防御写法）。

**做法**：
- `db.js` 统一导出三个工具：`inTransaction(callback)`、`mysqlLockSuffix()`、`isUniqueViolation(error)`；新建 `stable-json.js` 承接确定性序列化。
- 14 个模块的全部调用点替换为统一导入；条件式用法（如 `${forUpdate ? lock() : ''}`、`${lock ? LOCK : ''}`）一并替换。

**语义归一（本项唯一的实质行为变化，属缺陷修复）**：宽变体（booking/wellness-notifications/stage26/daily-brief）此前把**任何** `SQLITE_CONSTRAINT` 前缀错误（含 FOREIGNKEY/CHECK/NOTNULL）都当"重复"吞掉；统一后按窄变体语义——仅唯一键/主键冲突（`SQLITE_CONSTRAINT_UNIQUE`、errcode 2067/1555、`ER_DUP_ENTRY`/1062、better-sqlite3 风格消息）视为重复，外键/CHECK 失败原样抛出。逐点核对过原宽变体调用路径（时段插入、通知/跟进任务、简报）只会遇到唯一键冲突，收窄不影响正常路径；新增回归用例锁定两个方向（唯一冲突识别为重复、外键失败不吞）。

## 变更二：路由层拆分（G43）

**问题**：app.js 1515 行、全领域 131 个路由注册点混在一个文件，17 处路由 handler 内直接写多语句事务。

**做法**：app.js 收敛为 46 行组合根（CORS、body 解析、按域挂载、统一错误处理）；路由逐块纯搬运至 `src/routes/` 11 个域文件——`public`（11 路由）/`accounts`(6)/`booking`(10)/`meals`(15)/`health`(26)/`wellness`(22)/`environment`(2)/`assistant`(6)/`staff`(6)/`operations`(15)/`dean`(12)；共享中间件与助手（auth/optionalAuth/岗位门、`healthProfileState` 等查询助手）在 `src/routes/shared.js`（20 个导出）。各域仍注册完整 `/api/...` 路径于自己的 Router，URL 与匹配语义不变；无跨域同形路径，挂载顺序不敏感。

**核验**：生成器断言 131 个路由块与 20 个助手在新文件中各恰好出现一次；全量测试通过。

**遗留（后续优化，不在本次范围）**：路由 handler 内联的 17 处事务逻辑仍留在域路由文件中（G43 建议中的"下沉领域模块"部分）；`healthProfileState` 等业务查询助手在 routes/shared.js，理想归宿是健康领域模块。

## 变更三：助手域拆分（G47）

**问题**：assistant.js 2154 行，会话管理、运行生命周期、预算预留、四领域图编排、预约澄清、公开 API 混装。

**做法**：assistant.js 收敛为 794 行门面（普通聊天执行链 + 公开 API）；拆出五个模块，**依赖严格单向、无模块回引门面**：

| 模块 | 行数 | 职责 |
| --- | --- | --- |
| `assistant-config.js` | 76 | 环境上限常量、模型费率表、共享微助手（含 `endpointConfigured`/`assistantExecutionMode`） |
| `assistant-session.js` | 212 | 角色提示词、会话归属/状态校验、会话获取、健康自述采集 |
| `assistant-run.js` | 411 | 运行创建/步骤持久化、工具执行幂等缓存、`finishRun`、图预算预留 |
| `assistant-graph.js` | 462 | 四领域子代理执行与协调器编排 |
| `assistant-booking.js` | 249 | 预约时段澄清流程 |

分层方向：config ← session ← run ← graph / booking。`rolePrompts` 随会话模块移动（避免门面反向依赖）；`activeAssistantRuns`（运行去重 Set）仅门面使用、留在门面。

**核验**：生成器断言原文 26–2110 行每一行在新文件中恰好出现一次；门面对外导出与重构前完全一致（8 个函数，routes/assistant.js 与测试的导入零改动）；全量测试通过。
