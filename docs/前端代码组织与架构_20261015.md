## 2. 修改前端时找文件

| 要改什么 | 去哪 |
|---|---|
| 某个页面上的文字/交互 | 先按角色定位域文件（§1 的 components 表），组件名与旧 main.jsx 时代一致 |
| API 调用方式 / 401 行为 | `lib/request.js`（不要绕过它裸写 fetch） |
| 新页面的数据加载 | `lib/useQuery.js`（见 §4 约定） |
| 日期/时区显示 | `lib/date.js`（不要新写 Intl/时区代码） |
| 通用空态/加载/表单控件 | `shared/ui.jsx` |
| 导航、角色默认落点、岗位文案 | `app/navigation.js` |
| 全局样式 | `styles/`（注意层叠顺序，见 §5） |

## 3. 依赖方向（禁止反向）

```
main.jsx → app/ → components/* → shared/ + lib/
components/staff|dean|assistant → components/guest（复用客人域的展示组件与标签）
components/guest → assistant/assistant-parts（协作轨迹）
```

- `lib/` 与 `shared/` 不 import 任何 `components/`、`app/` 代码。
- 跨域复用已固定为 staff/dean/assistant → guest 单向（例如配餐工作台复用 `guest/meals.jsx` 的 `MealRestrictionReview`）；新增复用时保持这个方向，避免循环依赖。
- ESLint `no-undef`（`web/eslint.config.js`，`npm run lint -w web`）是拆分/搬移时的引用完整性门禁：vite build 对未导入标识符不报错，lint 报。

## 4. 关键机制与约定

- **数据加载一律用 `useQuery(loadFn, deps, options)`**（G20）：generation 计数使晚到旧响应不覆盖新数据；卸载时 abort；仅在成功时写入 `data`，失败保留旧数据并写 `error`。`options.fallbackMessage` 保留各页原错误文案；`options.onError` 用于需要 toast 的页面。手动刷新直接 `await load()`；带参手动刷新传 `load(arg)`（deps 关闭时由闭包取默认值）。
- **hash 路由（G17）**：工作区 section 与 `location.hash` 双向同步；刷新/返回/深链可恢复页面；退出登录清 hash；深链优先于岗位默认落点。登录前页面（Home/Login）不进 hash。未引入路由库。
- **错误边界（G19）**：根边界在 `main.jsx`；内容分发区（GuestView/StaffView）与 AssistantWidget 各有一层二级边界，按 `role+section` 重置——单页渲染异常给出恢复入口，不再整站白屏。
- **代码分割（G18）**：StaffView（含全部员工/管理页）、AssistantWidget、DeanTeam 为 `React.lazy` 分包；客人主线在首屏包。首屏 JS 约 311KB（拆分前 412KB）；CSS 随包就近拆分后首屏 CSS 约 127KB（拆分前 143KB），StaffView/AssistantWidget 各带自己的 CSS 分块。
- **通知事件契约**：`WELLNESS_NOTIFICATION_EVENT = 'wellness-notifications-updated'` 定义在 `guest/brief.jsx`，简报中心与助手共用；跨域需要时 import 该常量，不要重复写字符串。
- **DOM 契约冻结**：验收与演示脚本依赖稳定选择器（`login-*`、`data-testid="q24-*"`、`role=tab` 等）。重构/搬运时不得改 className、id、aria、可见文本。

## 5. CSS

- `styles/index.css` 是 eager 层全局入口，按**原层叠顺序** `@import` 各文件；组件级 `EnvironmentPanel.jsx` 仍就近导入自己的 `environment.css`（原状）。
- 阶段命名的文件已重命名为语义名：`org-stage11→health-review`、`stage13→project-admin`、`stage15→booking`、`stage16→meals`、`stage21→health-workspace`、`stage22→wellness-review`、`stage24→checkin-feedback`、`stage25→daily-brief`、`stage26→operations`、`styles→base`、`web-layout→layout`。
- **样式按组件就近导入已完成（G18 阶段 2，2026-10-16）**：`agent.css` 随 `staff/guests.jsx`、`operations.css` 随 `staff/OperationsWorkbench.jsx`（同入 StaffView 分包）、`assistant.css` 随 `AssistantWidget.jsx` 就近加载；客人主页共用的 `.metric-button`/`.assistant-sources` 规则移入 `base.css`（eager）。首屏 CSS 142.9KB→126.8KB，移动部分随分包按需加载。
- **层叠红线**：lazy 分包的 CSS 恒晚于全部 eager 文件加载——eager 层（`layout.css` 字号抬升、`release.css` 定位/布局覆盖、`overrides.css`）的覆盖意图必须继续由 eager 文件表达；移动文件中的对应声明视为死代码剪除，不要再写回。跨文件移动/新增样式前跑 `web/scripts/css-conflict-check.mjs` 与 `css-shorthand-conflict-check.mjs`（简写展开），改完用 `css-multiset-diff.mjs` 核对声明多重集。
- **新增样式**：eager 全局样式放进对应语义文件并在 `styles/index.css` 按需引入；分包组件私有样式直接在组件文件里 `import '../..../styles/xxx.css'` 就近加载。不要改动 `index.css` 中既有 import 的顺序（全局层叠依赖它）。
