# SQLite → MySQL 8 字段映射

本表以当前 SQLite/MySQL 运行 schema 和《海屿康养社区数据库设计.xlsx》的既有字段字典为基准。当前迁移版本为 v25，包括 48 张业务表、3 张助手运行追踪表及单独的 `schema_migrations` 元数据表。v12 增加 3 张心情/资源表，v17 增加 4 张初评/提取/疗程表，v18 增加 3 张审核/关注/本地通知表，v21 增加 `assistant_action_cards`，v23 增加 4 张预约执行/反馈/重规划表，v24 增加 2 张简报/关怀任务表，v25 增加 8 张机构运营表。v21–v23 还扩展健康来源、运行停止原因和心情修订字段。v13–v16 建立或扩展助手运行追踪。异步存储层把既有 API/SQLite 逻辑列翻译成 MySQL 物理列，并在读取时还原旧逻辑名。导入器仍只读明确指定的 SQLite 副本，导入 11 张基础表、2 张 Stage15 表和 4 张 Stage16 客人菜单/订单表，共 17 张数据表并核对 30 个关系；它不导入助手运行轨迹、确认卡、疗程审核或 Stage26 运营记录。菜品目录由目标 v10 迁移种子创建，不执行历史建库/种子 SQL。

## 时间、类型与约束

- 业务时间统一按 UTC 保存。SQLite 的 `...Z` 文本写入 MySQL `DATETIME(3)` 时去掉 `T`/`Z` 表示层符号，连接会话固定 `+00:00`；读取再还原为 ISO UTC。精度超过毫秒的输入拒绝或由 MySQL 明确报告，不静默改写业务时间。DATE 字段只保留年月日。
- 用户主键为 MySQL `VARCHAR(36)`；助手会话 ID 使用 `VARCHAR(64)`，可容纳当前 39 字符的 `as_<UUID>`，导入器不会截断更长来源值。
- SQLite INTEGER 自增主键迁为 `BIGINT UNSIGNED`。ID 原值显式导入；目标主键已存在时只记重复并跳过，不更新现值。超范围、截断、非法日期/JSON、CHECK 或外键失败都会中止并指出表/行。
- SQLite 的 TEXT/JSON 字符串与 MySQL VARCHAR/TEXT/JSON 类型并不等价。映射器不裁剪超长字符串；MySQL 目标长度、字符集、合法 JSON、非空和检查约束是导入门槛。
- 目标新增索引/外键/CHECK 以工作簿字典为准。SQLite 旧表中缺少目标外键的关系必须在导入前通过关系校验；不满足时阻止导入，不能跳过孤儿记录或静默置空。
- SQLite `schema_migrations` 与 MySQL `schema_migrations` 是迁移元数据表，不计入 48 张业务表或 3 张运行追踪表。v11 扩展 `health_records` 的结构化指标与撤回字段；v15 为 `assistant_messages` 增加 `run_id` 追踪索引；v18 扩展 `wellness_drafts`/`reservations` 并增加审核事件等表；v21 为 `health_records` 增加 `source_session_id` 外键；v22 给 `agent_runs` 增加 `stop_reason`；v23 增加预约执行/反馈/重规划表及心情修订号；v24 增加每日简报和关怀跟进表；v25 增加机构运营表。这些迁移扩展不纳入 17 张导入表。

## 数据版本与初始化边界
